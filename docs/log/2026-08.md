# 2026-08

Covers 2026-07-27 (v1.7.1) through 2026-08-05.

The theme of this cycle was pointing the tool at repositories we don't own and
discovering it was wrong most of the time. Nothing shipped to PyPI. That is the
correct outcome for a cycle spent finding out the ruler was bent.

## What moved, and why

**We scored five corporate repos as a demo dry-run and found four false
positives** ([#25](https://github.com/invigil/invigil/pull/25)). The worst:
`no-tracked-secrets` accused `aws-cli` and `playwright-python` of leaking
secrets that were *published certificates*, at blocker severity. That is the
most damaging thing this tool can do — a security accusation, wrong, about
someone else's repository, in public. #25 fixed those four and added the
`audit` profile, whose contract is that a check keeps its weight only if any
maintainer would concede the finding without first adopting Invigil's doctrine.

**A credibility pass retired what we couldn't back**
([#31](https://github.com/invigil/invigil/pull/31)). Empty public scaffolds and
the claims sitting next to them, plus four links in `docs/README.md` pointing at
pages that were never written. Documentation that promises pages it doesn't have
is the cheapest possible way to lose a reader.

**Alpha became legible rather than apologetic**
([#33](https://github.com/invigil/invigil/pull/33)). `docs/stability.md` now
states which surfaces are safe to automate against — CLI, exit codes, JSON
shape, badge JSON, MCP tool names, `.invigil.yml` v1 — and which are expected to
move: check verdicts, weights, gate assignment, grade, profile contents. Reports
carry `doctrine_version`, so a consumer can distinguish "our repo regressed"
from "the ruler moved". Beta was redefined as conditions rather than a date.

**Our own pins were lying about themselves**
([#32](https://github.com/invigil/invigil/pull/32)). The reusable-workflow
self-pins carried version comments that didn't match the SHA. `actions-sha-pinned`
reads that comment, so a wrong label is false supply-chain evidence about
ourselves — the third time a trailing comment has been wrong.

**Phase 2: 27 third-party repos scored under the `audit` profile, 448 findings,
106 audited by hand so far.** The sample was built to stress naming conventions
rather than to collect prestigious names: `tqdm` for `LICENCE`, `jq` and `curl`
for `COPYING`, `ripgrep` and `bat` for Rust dual-licensing, `chalk` for
lowercase `readme.md`, the Sphinx projects for `docs/index.rst`. **Across the
presence-style checks, 66 of 106 audited findings were false positives — 62%.**
Three of those checks were wrong every single time they fired:
`no-tracked-secrets` (13/13), `license-present` (7/7), `readme-present` (4/4).

The one check audited outside that group came back clean: `actions-sha-pinned`,
17 findings, **zero** false positives. It is the check whose trailing-comment
trust has bitten us three times on our own repository, and on other people's it
was right every time. Folding it into the denominator moves the rate from 62% to
54% — which is why the published page gives per-check numbers and states the
denominator rather than leading with one blended figure.

The `no-tracked-secrets` results are the ones that matter. #25 had fixed that
class *by path*, and every repo that files throwaway key material outside
`tests/` walked straight back into it — including `jqlang/jq`, where we flagged
`sig/jq-release-*.key`, the PGP public keys you verify jq releases *with*. We
accused a project of leaking a secret by pointing at its published public key.

**The fix was to stop asking about paths.** On the (still unmerged) branch
`fix/phase2-false-positives`: `no-tracked-secrets` now reads file contents — a
PEM whose header says `PUBLIC KEY` is not a leak, and a `.env` holding no
credential-shaped value is not one either. A new `Context.first_matching()`
replaced `first_existing()` across seven checks; the old one asked "did you use
our spelling", the new one asks "is it there". `readme-heading-hierarchy` now
counts HTML `<h1>`/`<h2>`, because the centred-banner README is a mainstream
convention and we were reading `numpy`, `axios`, `fastapi`, `bat` and
`prometheus` as untitled documents.

Re-scoring the same 27 repos: **448 → 402 findings, 13 repos scoring no gate at
all → 0, five blocker-severity accusations → none.** 62 new tests, each naming
the repository that exposed the defect.

**Release pages stopped announcing Dependabot**
([#34](https://github.com/invigil/invigil/pull/34), open). `generate_release_notes`
had made the v1.7.1 page open with three version bumps and "@rrskris made their
first contribution" — about the repo owner — while `--format ai-badge`, the
feature it shipped, went unmentioned. Notes now come from `CHANGELOG.md`, and a
release with no matching section fails rather than shipping blank.

## What did not move

**The `ai-ready` badge bug, open since ~2026-07-27.** `badges/invigil-ai.json`
publishes 7/7 while every local path reports 8/8 — one `ai` check SKIPs on the
runner and we don't know which. Five hypotheses are disproven: `_repo_*`
contamination, multi-path portfolio, shallow/grafted git history, the `[mcp]`
extra, the published-wheel path. The next step is a diagnostic inside CI, and it
has not been taken. This is the first entry to name it. If it appears in the
next one unchanged, that is the signal to stop guessing and instrument.

**No release since v1.7.1 on 2026-07-27.** Nine days. The work of this cycle is
real but none of it is installable.

**331 of 402 findings are still unaudited** — mostly checks that fire
near-universally: `signed-releases-sbom` 27/27, `smoke-published` 26/27,
`coverage-gate` 26/27, `good-first-issues` 26/27. A check that fires on 27 of 27
diverse, well-run projects is not finding 27 defects. Each still needs a call:
true observation of something nobody does, or another detection bug?

**The sample is 27 against a Beta bar of 30**, and under-represents AsciiDoc (3),
Java (2) and non-English-primary projects (0). Beta condition 1 is not met.

**Bus factor is still 1.** Beta condition 3. Scorecard measures the same fact
from outside and gives `Code-Review` a 0: *0/25 approved changesets*. Every
change to this repository has been merged by the person who wrote it.

**`invigil init` does not exist.** The config wall is what keeps the Cold-Start
Gate — the actual differentiator — switched off for anyone who tries the tool
casually.

**`PORTFOLIO.md` is stale**, dated 2026-07-27 and still claiming 34/34 against a
current 35/35. The portfolio workflow ran on 2026-08-03 and committed nothing.

## Decisions taken and closed

- **Stay Alpha, and make Alpha legible.** The label is not a disclaimer to route
  around; it is an accurate description of a tool whose ruler is still being
  calibrated. Beta is a set of conditions, not a date.
- **Never lead with letter grades.** Nobody adopts a CI gate in order to be
  graded. Lead with `smoke-published`, which fails 5/5 across five companies and
  survived the false-positive cleanup intact.
- **Any public scoring of repositories we don't own stays gated** behind a
  published false-positive rate. Naming a repo because *we* were wrong about it
  is on the right side of that line; ranking or grading it is not.
- **"Adopt my rubric" is not on the table.** Scorecard had institutional backing
  this project does not. Utility per individual check is the only route.
- **A build log is not promotion**, and is therefore not subject to that gate.
  Publishing our own work — and our own tool's errors — is a different act from
  publishing judgements about other people's repositories.
- **The log lives in the repo**, versioned with the code, so it survives the
  private planning file and stays legible to agents reading the tree.
- **The false-positive audit ships standalone**, not folded into a roundup.
- **`license-apache2` is weight 0 in the `audit` profile.** Telling MIT and BSD
  projects their license "is not Apache-2.0" is house style with no claim to
  universality.
