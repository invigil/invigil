# Build log

One entry per month, newest first. What moved, what didn't, what got decided, and
the numbers — including the unflattering ones.

The log exists because the reasoning behind this project has been living in a
private file. Releases are event-driven and say what changed; a log is
calendar-driven and says what it cost, what stalled, and which arguments are
closed so they stop being reopened. Both are needed and neither substitutes.

Every entry carries the same four sections. The last two are what make this a
record rather than a highlight reel:

- **What moved, and why** — shipped work, with the reasoning.
- **What did not move** — stalls, named. A stall that appears in three
  consecutive entries is a decision being avoided.
- **Decisions taken and closed** — so they stay closed.
- **Metrics, unspun** — self-score, tests, Scorecard, adopters, false-positive
  rate. The numbers that look bad are load-bearing: they are what make the rest
  believable.

This is a build log, not an announcement channel. It records our own work and
our own tool's errors. It is not a place where other people's repositories get
scored or ranked: publishing that Invigil was wrong about a repo is a different
act from publishing a judgement of it, and only the first one happens here.
